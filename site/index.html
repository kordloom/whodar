04 // Connections

It finds the connections nobody wrote down.

Everything above runs through people. This does not. Two areas changed in the same commit, fixed under one ticket, or written up on one page belong together whoever did the work, which makes it the only thing whodar knows about your systems that does not depend on knowing who owns them. No taxonomy to maintain, no model, no one to ask.

TOGETHER

What moves as one thing

Ask about one area and see the areas it actually travels with, learned from work that touched both. Git, Jira, Confluence, and GitHub each contribute it the same way.

CROSSINGS

The link one person holds

Two areas, both well covered, where every piece of work crossing between them has only ever been done by one person. What leaves with them is not either area. It is knowing the two belong together.

JOINED WORK

One large risk, not ten small ones

Connected areas that all lead back to the same person. Whoever picks that up has to learn the whole of it at once, and a list of areas one at a time never shows it.

Why it is different
No taxonomy to maintainNo modelLearned from the work itself

// Private by design

Your org's knowledge never leaves your walls.

whodar runs entirely in your own environment, so the graph of who-knows-what stays yours. No account, no vendor in the loop, nothing to send off for a security review. It reads the tools your team already uses, builds one index on your own disk, and answers from there. Self-hosting is the point, not a limitation. It is what lets you wire whodar into work and keep people data private.

What you run
  • One binary. The CLI, the local web app, the self-hosted Slack bot, and the MCP server all live in a single download.
  • In your own walls. It runs on your laptop or a server you control, with your own tokens, and answers from there.
  • Local by default. It reads the tools you use to build one index that stays on your machine.
What you avoid
  • A security review. Nothing is shipped to a vendor to vet, so there is no data-processing agreement and no third party trusted with your people data.
  • An account or lock-in. Nothing to sign up for and no marketplace gatekeeper. Remove the binary and the index, and nothing of yours is left anywhere.
  • Data leaving the building. The index and every answer stay in your walls, so whodar runs fine on a locked-down or air-gapped host.
Coming soon

A fully hosted whodar you add to Slack in one click. For teams that want zero setup and are fine with a managed service running it for them. The self-hosted tool stays exactly as it is. The hosted tier is a separate option, not a replacement.

06 // Egress control

You decide what a model ever sees.

Indexed work data is sensitive, so whodar controls what a model can see. The default is strict: answers are computed locally and nothing is sent anywhere.

  • Local by default. Keyword answers need no model and no network. Nothing is uploaded, ever.
  • Encrypted at rest. Set a key and the on-disk index is sealed with AES-256, so a stolen disk or a stray backup cannot read it.
  • Cloud models are opt-in. Claude, Gemini, and OpenAI run only when you turn them on, and only to their known hosts.
  • Org lock. An administrator can pin the policy in a file that user flags and environment variables cannot loosen.
Egress policy3 levels
strictDefault. Nothing leaves the machine. Only the keyword engine and a local model are allowed.
redactedOpt-in. A cloud model sees your question and anonymized numbered candidates, never names, emails, channels, or message text.
openFull detail. For teams that want the richest answer and accept sending candidate detail to their chosen model.
07 // Ranking

Works great with no model. Even better with one.

Keyword always works with nothing installed. Meaning and AI are layers you add, never a dependency. Bring a local model through Ollama, or your own key for Claude, ChatGPT, or Gemini, and whodar still decides what they are allowed to see.

Keyword

Exact word match with typo tolerance. Deterministic, instant, and always available.

Needs nothing

Meaning

Matches by meaning, so "failed payments" finds the person tagged "billing retries" with no shared word.

Local embeddings via Ollama

AI

A model re-ranks the candidates and writes a recommendation. Pick local Ollama, Claude, Gemini, or ChatGPT.

Local or cloud, your choice
08 // Get whodar

Install once. Add it wherever you ask questions.

One binary holds every surface. Pick one below for the exact steps.

whodar is a single binary. The CLI, the local web app, the Slack bot, and the MCP server all live inside it. There is no separate desktop app to install: you run it, and it serves the web UI in your browser.

# macOS with Homebrew
brew trust kordloom/tap   # newer Homebrew asks once per third-party tap
brew install kordloom/tap/whodar

# any platform with Go
go install github.com/kordloom/whodar@latest
↓ Prebuilt binaries · macOS · Linux · Windows
